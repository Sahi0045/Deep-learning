# AIRTLab Violence Detection Dataset — local preparation

This directory holds the **AIRTLab *A dataset for automatic violence detection
in videos*** as prepared for this project: the source videos, official
annotation CSVs, extracted frame sequences, and a `manifest.csv` that the
training/evaluation pipeline consumes.

## Contents

```
datasets/airtlab_violence/
├── action-class-occurrences.csv     # official action tags per scene
├── nonviolent-action-classes.csv    # official nonviolent action tags
├── violent-action-classes.csv       # official violent action tags
├── non-violent/{cam1,cam2}/*.mp4     # 60 nonviolent scenes x 2 cameras
├── violent/{cam1,cam2}/*.mp4         # 115 violent scenes x 2 cameras
├── frames/<class>/<video_id>/*.jpg  # 8 evenly-spaced frames per video
└── manifest.csv                      # canonical split + frame mapping
```

350 videos total (175 scenes x 2 synchronised cameras).

## Three-class mapping

The official per-video action tags are collapsed into three target classes:

| Class | Source scenes | Actions included |
|-------|--------------|------------------|
| `nonviolent` | 60 scenes (120 videos) | hug, highfive, handshake, gesture |
| `unarmed_assault` | 55 scenes (110 videos) | slap, punch, kick, push, choke |
| `armed_assault` | 60 scenes (120 videos) | stab, club, gunshot threat |

The split (armed vs. unarmed) is driven by the weapon-action set
`{club, stab, gunshot}` in `violent-action-classes.csv`; everything else
labelled violent becomes `unarmed_assault`.

## Scene-grouped splitting

Splits are stratified **by `scene_id`**, never by frame, so that:

- all 8 frames of one clip stay in one split, and
- the two camera views (`cam1`, `cam2`) of the *same physical event* never
  cross a split boundary (which would leak the scene into both train and test).

The default split is 70 / 15 / 15 (train / val / test) by scene, verified by
`data_pipeline.verify_zero_group_leakage`, which raises if any group appears in
more than one split. With seed 42 this yields 122 / 26 / 27 scenes.

## `manifest.csv` schema

One row per video (camera view). Columns:

| Column | Meaning |
|--------|---------|
| `video_id` | `<scene_id>_<cam>` |
| `scene_id` | `nonviolent_scene_NNN` / `violent_scene_NNN` (split key) |
| `camera_id` | `cam1` or `cam2` |
| `video_path` | relative path to the source `.mp4` |
| `frames_dir` | directory of extracted frames |
| `frame_paths` | `;`-separated ordered frame file paths (length = `sequence_length`) |
| `num_frames` | frames extracted |
| `total_video_frames`, `fps` | source video metadata |
| `class_name` | one of the three target classes |
| `class_id` | 0/1/2 |
| `binary_label` | `nonviolent` / `violent` |
| `raw_actions` | comma-separated official action tags |
| `split` | `train` / `val` / `test` |

## (Re)generation

Everything in this directory (except the source MP4s and official CSVs) is
regenerated by `download_real_data.py`, which downloads the videos, extracts
frames, assigns splits, writes `manifest.csv`, and syncs `training_data/`:

```bash
python3 download_real_data.py            # download + prepare
python3 download_real_data.py --threads 8
```

The extracted frame count is `sequence_length` (default 8) per video at
`image_size` (default 128x128).

## Notes

- `exclude_synthetic=True` (default) means frames whose names match the
  synthetic generator's patterns are filtered out; this dataset contains only
  real, human-annotated frames, so the filter is a safety net.
- This dataset depicts staged physical violence for research. Use care in any
  downstream deployment; it is not appropriate for surveillance of real people
  without consent, oversight, and bias evaluation.
